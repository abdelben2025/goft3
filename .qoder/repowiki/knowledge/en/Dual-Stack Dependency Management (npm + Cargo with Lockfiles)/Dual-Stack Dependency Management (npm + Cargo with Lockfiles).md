## Approach

The GOFT3 desktop app manages dependencies through two independent package managers, one per runtime:

- **Frontend (Electron + Tauri UI)** — npm / Node.js, declared in `package.json`, locked by `package-lock.json`.
- **Backend (Tauri Rust binary)** — Cargo, declared in `src-tauri/Cargo.toml`, locked by `src-tauri/Cargo.lock`.

There is no vendoring of third-party source code; all packages are resolved from public registries at install/build time. No private registry, `.npmrc`, or GOPRIVATE configuration is present.

## Key Files

- `package.json` — frontend dependency manifest (dependencies + devDependencies), build scripts, and electron-builder config.
- `package-lock.json` — deterministic npm lockfile consumed by CI via `npm ci`.
- `src-tauri/Cargo.toml` — Rust crate manifest for the Tauri backend (`goft3_lib`).
- `src-tauri/Cargo.lock` — Cargo lockfile (referenced by the CI cache key).
- `.github/workflows/release.yml` — CI pipeline that installs both stacks and publishes signed NSIS bundles.

## Architecture & Conventions

### Frontend (npm)

- Dependencies are pinned with caret ranges (`^x.y.z`) rather than exact versions, allowing minor/patch updates within a major version.
- The `engines` field constrains the runtime to `node >=20.0.0` and `npm >=10.0.0`.
- A top-level `overrides` block pins transitive dependencies to specific versions (e.g. `uuid ^11.0.0`, `postcss ^8.5.3`, `esbuild ^0.25.0`, `ws ^8.20.2`, `lodash ^4.17.23`, `minimatch ^9.0.5`, `braces ^3.0.3`, `app-builder-lib ^26.17.0`, `@electron/get ^5.1.0`). This is used to force patched versions of vulnerable or incompatible transitive deps pulled in by Electron/electron-builder.
- Fonts are bundled as npm packages under `@fontsource/*` (`amiri`, `cairo`, `tajawal`) and imported directly in `index.tsx`.
- The project is marked `"private": true`, so it is not intended to be published to the npm registry.
- Build tooling: Vite (`vite.config.js`), TailwindCSS, PostCSS, ESLint (typescript-eslint v9), Vitest for tests.
- Desktop packaging: electron-builder configured inline in `package.json` under `build` (NSIS on Windows, deb on Linux) producing artifacts into `release/`.

### Backend (Cargo)

- Single crate `goft3` (lib name `goft3_lib`) compiled as `staticlib`, `cdylib`, and `rlib` so Tauri can link against it.
- Edition 2021; dependencies use semver-compatible ranges (e.g. `tauri = "2"`, `rusqlite = "0.31"`, `serde = "1"`, `aes-gcm = "0.10"`).
- Platform-specific dependency via `[target.'cfg(windows)'.dependencies]` pulling `windows-sys` only on Windows.
- Security-related crates: `aes-gcm`, `pbkdf2`, `sha2`, `getrandom` for encrypted backups and password hashing.
- Database: `rusqlite` with the `bundled` feature (bundles SQLite C library).

### CI & Reproducibility

- GitHub Actions runs on `windows-latest` and triggers on tags matching `v*`.
- Node setup uses `actions/setup-node@v5` with `cache: npm`; Rust setup uses `dtolnay/rust-toolchain@stable`.
- Cargo cache keys off `hashFiles('**/Cargo.lock')` and caches `~/.cargo/registry`, `~/.cargo/git`, and `src-tauri/target`.
- Frontend install uses `npm ci` (strict, lockfile-enforced) — no interactive prompts, fails if lockfile drifts.
- Release artifacts: signed NSIS installer (`*-setup.exe`, `*-setup.exe.sig`) plus `latest.json` generated by `scripts/make-latest-json.ps1`, uploaded via `softprops/action-gh-release@v3`.

## Conventions & Constraints

- **Deterministic installs**: CI uses `npm ci` and Cargo's `Cargo.lock` (cached by hash); local development should use `npm install` / `cargo build` against these lockfiles.
- **No private registries**: All packages resolve from `https://registry.npmjs.org` (visible in `package-lock.json` `resolved` URLs) and crates.io; no `.npmrc`, `GOPRIVATE`, or custom registry entries exist.
- **Version policy**: Caret ranges in manifests allow compatible updates; critical transitive vulnerabilities are addressed centrally via `overrides` in `package.json` rather than patch files.
- **Engine pinning**: `node >=20.0.0` and `npm >=10.0.0` are enforced by npm when installing.
- **Dual-version alignment**: The frontend `version` in `package.json` and the Rust `version` in `src-tauri/Cargo.toml` are kept in sync (both `1.1.19`), since the release workflow reads the version from `package.json` to generate `latest.json`.
- **Vendoring**: Not used — no `vendor/` directory, no checked-in tarballs; all third-party code is fetched at install time.
