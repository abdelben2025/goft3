Flat collection of React functional components under `pages/`, each exported as a default component and consumed by the app router. Pages fall into four internal groups:
- Data-entry / list pages (`OperationsPage`, `DocumentsPage`, `BeneficiairesPage`, `UsersPage`, `SettingsPage`, `CategoriePage`, `DirectionPage`, `ProgrammePage`, `RubriquePage`) that read/write via `useData()` from `../context/DataContext` and expose add/edit/delete through modals.
- Detail pages (`OperationDetailsPage`, `DocumentDetailsPage`, `FinancialStatusPage`, `FinancialStatusByStructurePage`, `ProjectTrackingPage`, `VisaedEngagementsPage`, `PaymentClaimsPage`, `MonthlyCommitmentsPage`, `MonthlyPaymentsPage`, `AeInsufficiencyPage`, `UnregisteredDocumentsPage`).
- Print-only pages prefixed with `Print*` (`PrintOperationsTablePage`, `PrintFinancialStatusPage`, `PrintEngagementPage`, `PrintPaiementPage`, `PrintBordereauPage`, `PrintCertificatPage`, `PrintDeclarationPage`, `PrintMandatPage`, `PrintRevenueNoticePage`, etc.) — these recompute the same business aggregates as their interactive counterparts but render minimal, printer-friendly markup without edit controls.
- Shell/navigation pages (`HomePage`, `LoginPage`, `CustomReportPage`, `LotsReportPage`).

All pages depend on shared layers outside this module: `../types` for the `Page` enum and domain models, `../context/DataContext` for the in-memory DB plus CRUD ops, `../context/LanguageContext` for i18n (`t`, `dir`), `../components/*` for reusable UI primitives (`PageWrapper`, `Modal`, `ConfirmActionModal`, `Card`, `CustomDropdown`, form fragments under `../components/forms/`), and `../services/tauriService` / `../services/supabaseClient` for desktop/offline persistence and cloud sync. Navigation is centralized via a `navigate(page: Page, id?, tab?)` prop rather than React Router, so every page declares its own `interface Props { navigate, currentUser, ... }`. Print pages are routed to via string literals like `'PRINT_OPERATIONS_TABLE'` matching the `Page` enum.
