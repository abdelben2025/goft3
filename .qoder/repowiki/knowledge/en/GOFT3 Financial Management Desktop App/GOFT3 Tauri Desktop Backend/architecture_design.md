Single Rust crate (`goft3_lib`) built as `staticlib` + `cdylib` + `rlib` via Cargo.toml. Entry point `src/main.rs` is a thin shim that calls `goft3_lib::run()` from `src/lib.rs`, which wires the Tauri 2 runtime: registers plugins (opener, dialog, updater, process), initializes the SQLite database at startup, and exposes ~20 commands through `tauri::generate_handler!`. Internal layering:
- `commands.rs` — all `#[tauri::command]` handlers; every handler validates table names against an `ALLOWED_TABLES` whitelist and column identifiers via `validate_identifier`, then builds parameterized SQL through `json_to_sql`.
- `db.rs` — schema definition (CREATE TABLE statements for 20 tables), WAL/foreign-key pragmas, per-user path resolution under `app_data_dir()`, idempotent migration checks, and default admin seeding.
- `security.rs` — AES-256-GCM backup encryption with PBKDF2 key derivation (magic header `GOFT3BK2`), plus optional Windows-only EFS encryption of the live `.db`, `-wal`, and `-shm` files.
Dependency direction is one-way: `commands` → `db` + `security`; `lib` orchestrates wiring; `main` only boots it. The frontend is a separate web app served from `../dist` during dev/build per `tauri.conf.json`, communicating exclusively through the typed invoke handler.
