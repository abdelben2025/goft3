Two-tier layout under `components/`:
- Flat primitives at the root (`Modal.tsx`, `Card.tsx`, `Toast.tsx`, `LoadingToast.tsx`, `ConfirmActionModal.tsx`, `BeneficiaryDetailsModal.tsx`, `CustomDropdown.tsx`, `DateInputField.tsx`, `DocumentInfoBox.tsx`, `DocumentRow.tsx`, `OperationRow.tsx`, `NotificationBell.tsx`, `EventTicker.tsx`, `IdleLockScreen.tsx`, `SplashScreen.tsx`) — stateless or self-contained presentational components styled with Tailwind CSS.
- A `forms/` sub-package of one `AddXxxForm.tsx` per domain entity (Beneficiary, Bordereau, Categorie, Cp, Direction, Document, Engagement, Lot, LotPiece, Ods, Operation, Paiement, Programme, Rubrique, RubriqueOp, SProgramme, Scategorie, ScategorieOp, User), each exporting a default component used by parent pages as modal content.

Dependency direction is strictly inward: components consume shared types from `../types`, global store via `useData()` from `../context/DataContext`, language/direction via `useLanguage()` from `../context/LanguageContext`, and cross-cutting utilities (`formatCurrency`, `hashPassword`). Cross-component composition happens through props only; there is no internal index barrel. The draggable `Modal` wrapper is the canonical container for all forms and detail modals, providing keyboard Escape handling, focus management, overlay click-to-close, and pointer-based dragging.
