## System / Approach

The GOFT3 desktop app uses **Tailwind CSS** as its sole styling system, built via Vite + PostCSS (autoprefixer). There is no component library (no shadcn, MUI, AntD, etc.), no SCSS/Sass pipeline, and no CSS-in-JS runtime — styling is composed directly from Tailwind utility classes on JSX elements.

PostCSS configuration (`postcss.config.js`) enables only `tailwindcss` and `autoprefixer`; there are no additional plugins such as `@tailwindcss/forms`, `@tailwindcss/typography`, or design-token preprocessors.

## Key Files

- `tailwind.config.js` — single source of Tailwind config: content globs, font override, empty plugins array.
- `index.css` — global stylesheet that imports Tailwind layers, defines all custom keyframe animations, print overrides, scrollbar theming, and the Cairo font application.
- `components/*.tsx` — reusable UI primitives (Card, Modal, Toast, ConfirmActionModal, CustomDropdown, DateInputField, PageWrapper, SplashScreen, etc.) styled entirely with inline Tailwind class strings.
- `pages/*.tsx` — page-level components composing shared components; styling lives in the same files as markup.
- `i18n/translations.ts` — Arabic-only translation resource consumed by the UI (the app is monolingual Arabic).

## Architecture and Conventions

### Typography
- The default sans font stack is overridden to prioritize **Cairo** (an Arabic-friendly typeface) followed by `Segoe UI, Tahoma, Geneva, Verdana, sans-serif`. This is declared in `tailwind.config.js` under `theme.extend.fontFamily.sans`.
- A global rule in `index.css` applies `font-family: 'Cairo', sans-serif` to `body`.
- Latin text inside tables and forms is forced uppercase globally via `table td, table th, input, textarea { text-transform: uppercase; font-size: 0.82rem; font-weight: 500; }`, with a `.normal-case` override class available for exceptions.

### Color Palette
- No custom color palette is defined in `tailwind.config.js`; the app relies exclusively on Tailwind's built-in palette (e.g., `bg-gray-50`, `bg-white`, `text-gray-500`, `text-gray-800`, `border-gray-100`).
- Accent colors used across components come from icon libraries (e.g., FontAwesome classes like `bg-blue-600`, `bg-green-600`, `bg-red-600`) passed as props rather than from design tokens.

### Layout & Spacing
- Layout is composed from Tailwind flexbox utilities (`flex`, `items-center`, `justify-between`, `flex-col`, `shrink-0`, `overflow-hidden`).
- Spacing uses Tailwind's spacing scale (`p-1`, `p-2`, `p-3`, `p-4`, `mr-1`, `mr-3`).
- Responsive behavior uses Tailwind's responsive prefixes (e.g., `sm:p-4`, `sm:text-lg`, `sm:text-xs`) — no media queries beyond those generated by Tailwind.

### Animations
All motion is hand-written CSS keyframes in `index.css`, exposed as utility classes:
- Highlight pulses: `.animate-highlight-amber`, `.animate-highlight-red`, `.animate-highlight-blue` (used to draw attention to rows/cells).
- Entrance transitions: `.animate-bounce-in-right`, `.animate-slide-up`, `.animate-slide-down`.
- Feedback loops: `.animate-pulse-green`, `.animate-loading-bar`, `.animate-blink-red`.

These are not part of Tailwind's animation plugin; they are custom `@keyframes` blocks in the global stylesheet.

### Print Styles
A dedicated `@media print` block in `index.css` handles printing:
- Hides `.no-print` elements.
- Resets `html, body` height/margins/padding to avoid blank pages.
- Overrides `.min-h-screen` to `min-height: 0`.
- Forces `#print-content` to static positioning so print layouts flow naturally.

### Scrollbar Theming
Custom webkit/Firefox scrollbars use sky-blue tones (`#20bdec` / `sky-700` for thumb, `#e0f2fe` / `sky-100` for track) applied globally via `::-webkit-scrollbar-*` selectors and `scrollbar-width` / `scrollbar-color` for Firefox.

### RTL / Bidi Handling
- Inputs and textareas set `unicode-bidi: plaintext` and `text-align: start` so mixed Arabic/Latin content aligns correctly regardless of direction.
- Placeholders explicitly disable uppercase transformation (`input::placeholder, textarea::placeholder { text-transform: none; }`).

### Component Styling Pattern
Reusable components follow a consistent pattern:
- Props drive visual variants (e.g., `Card` accepts `compact`, `isLargeValue`, `color`; `Modal` accepts `maxWidth` mapped to Tailwind `max-w-*` classes).
- All styling is inline Tailwind class strings — no CSS modules, no styled-components, no CSS-in-JS objects.
- Icons are rendered via `<i className="...">` using an external icon font (FontAwesome classes like `fa-solid fa-user`, `fa-solid fa-file`, etc.).

## Conventions and Constraints

- **No custom Tailwind theme extensions beyond fonts**: `tailwind.config.js` extends only `fontFamily`; no custom colors, spacing, breakpoints, shadows, or radii are added.
- **No SCSS/Sass**: the build chain is Vite → PostCSS → Tailwind → autoprefixer; there are no `.scss` files.
- **No component-scoped CSS**: styles live either as inline Tailwind classes in `.tsx` files or as global rules/animations in `index.css`.
- **Content scanning is explicit**: `tailwind.config.js` lists exact globs (`./components/**/*.{js,ts,jsx,tsx}`, `./pages/**/*.{js,ts,jsx,tsx}`, `./context/**/*.{js,ts,jsx,tsx}`, `./services/**/*.{js,ts,jsx,tsx}`, `./utils/**/*.{js,ts,jsx,tsx}`), so any file outside these paths will have its Tailwind classes purged at build time.
- **Font family is centralized**: the Cairo font declaration lives only in `tailwind.config.js`'s `theme.extend.fontFamily.sans`; components should not hardcode `font-family`.
- **Animations are centralized**: all `@keyframes` and their corresponding `.animate-*` classes live in `index.css`; new animations should be added there rather than per-component.
- **Print layout is centralized**: print-specific overrides live in the `@media print` block in `index.css`; components should use the `.no-print` utility class to hide interactive chrome during printing.
